### 오늘의 핵심 대화

- 토스증권 Open API 기반 FastAPI 백엔드 구조를 공식 문서 기준으로 재구성했다.
- 공식 문서 주소는 `https://developers.tossinvest.com/docs`이며, REST API 기본 주소는 `https://openapi.tossinvest.com`이다.
- OAuth 2.0 Client Credentials Grant 방식으로 토큰을 발급받고, 랭킹 API에서 국내 주식 상승률, 하락률, 거래대금 랭킹을 수집한다.
- FastAPI는 수집된 데이터를 Redis에 저장하고, 프론트엔드 또는 Chrome Extension에는 `/api/v1/market-trend`로 제공한다.
- `/docs`는 사용자용 주식 화면이 아니라 FastAPI API를 확인하고 테스트하는 Swagger UI라는 점을 확인했다.

### 발생한 에러와 원인

#### 1. `127.0.0.1:8000` 연결 거부

증상:

- `http://127.0.0.1:8000/health` 연결 거부
- `http://127.0.0.1:8000/docs` 연결 거부

원인:

- Uvicorn이 서버를 열기 전에 설정 로딩 단계에서 종료됐다.
- `.env`에 이전 버전의 `TOSS_ACCESS_TOKEN`만 있었고, 현재 코드가 요구하는 `TOSS_CLIENT_ID`, `TOSS_CLIENT_SECRET`이 없었다.

해결:

```env
TOSS_CLIENT_ID=실제_client_id
TOSS_CLIENT_SECRET=실제_client_secret
```

필수 인증 키를 `.env`에 추가한 뒤 FastAPI import와 서버 기동을 확인했다.

#### 2. 토큰 요청 `403 edge-blocked`

증상:

```text
POST https://openapi.tossinvest.com/v1/oauth2/token
403 Forbidden
code: edge-blocked
```

원인:

- `.env`의 `TOSS_API_BASE_URL`에 `/v1`이 포함되어 토큰 주소가 잘못 조합됐다.

잘못된 값:

```env
TOSS_API_BASE_URL=https://openapi.tossinvest.com/v1
```

수정한 값:

```env
TOSS_API_BASE_URL=https://openapi.tossinvest.com
```

이후 정상 호출 주소는 다음과 같다.

```text
POST https://openapi.tossinvest.com/oauth2/token
GET https://openapi.tossinvest.com/api/v1/rankings
```

#### 3. 랭킹 데이터 없음 `HTTP 503`

원인:

- Redis가 비어 있었던 것이 아니라, 기존 Uvicorn 프로세스가 이전 `.env` 설정을 계속 사용하고 있었다.
- 서버를 재시작해 최신 환경변수를 다시 읽도록 했다.

해결 후 확인 결과:

```text
토큰 발급: HTTP 200
상승 랭킹: 50개 수집
하락 랭킹: 50개 수집
거래대금 랭킹: 50개 수집
/api/v1/market-trend: HTTP 200
source: redis
```

## 2026-09-30 작업 기록

### 종목명 및 화면 배치

- `app/collector.py` 종목명 보강 코드의 들여쓰기 오류를 수정했다. 오류 당시 Uvicorn 하위 프로세스가 앱을 import하지 못해 연결이 거부됐다.
- `app/api/routes.py`의 필드 조회 함수가 `null`이나 빈 문자열에서 멈추지 않고 다음 이름 별칭을 찾도록 했다.
- 종목명 표시에서 이름이 없으면 심볼을 표시하고, 분야·시장 값이 종목명처럼 잘못 노출되지 않도록 했다.
- 현재 화면 순서는 AI 요약 → 강세/주의 분야 카드 → 종목 랭킹 → 상세 분야 표다. 강세/주의 카드는 상단에 유지하고, 긴 상세 분야 표 때문에 종목명이 화면 아래로 밀리지 않도록 랭킹 표를 앞에 배치했다.
- 실제 `http://127.0.0.1:9000/market-trend`에서 통합·국장 탭을 확인했다. 통합에는 미국 종목명, 국장에는 `빅웨이브로보틱스`, `글로벌테크놀로지` 등 이름이 표시됐다. `/health`와 랭킹 API도 HTTP 200을 반환했다.
- 브라우저에 남은 과거 `ERR_CONNECTION_REFUSED`는 해당 시점 서버가 응답하지 않았던 기록이다. 현재 확인 시점에는 9000번 서버와 API가 응답했다.

### 원본 데이터 뷰어

- 새 파일 `raw_data_viewer.py`를 추가했다. 기존 원본 랭킹 API를 직접 호출하며, 정규화나 종목명 보강은 하지 않는다.
- 화면은 검은 배경과 원본 JSON 텍스트만 표시하고, 필드와 값은 바꾸지 않은 채 줄바꿈/들여쓰기만 적용한다.
- 원본 Ranking API 응답에는 종목명 대신 `symbol`이 들어온다. 따라서 이름이 필요한 가공 화면은 종목 마스터 조회로 보강하지만, 원본 뷰어에 이름이 없는 것은 정상이다.
- 원본 뷰어 주소: `http://127.0.0.1:9100/`
- 실행 명령: `py -m uvicorn raw_data_viewer:app --reload --host 127.0.0.1 --port 9100`
- 원본 뷰어도 HTTP 200 및 JSON 응답을 확인했다.

- `app/sector_news.py`: Google 뉴스 RSS로 분야명 + 시총 상위 3종목 기사를 수집한다. 제목에 대상 이름이 없는 기사는 버리고(예: '조선' 검색의 '조선일보'), 비슷한 제목은 하나로 합쳐 `similar_count`를 남긴다.

  - 랭킹 표본 해석: 기존 `interpret_market` 결과와 상승·하락·거래대금 상위 종목. 표본임을 화면에 표시한다.
- 요약(제목·종합 해석·핵심 포인트)은 AI가 위 자료만 근거로 쓰고, AI가 실패하면 규칙 기반 문장으로 대체한다. 화면에 `AI 분석`/`규칙 기반 분석`이 표시된다. 결과는 5분 캐시하고, AI 실패나 랭킹 캐시 공백 때는 90초만 캐시한다.
- 화면의 지수·종목을 누르면 주가 흐름 탭, 분야를 누르면 분야 흐름·기사 탭으로 넘어간다. `/api/v1/market-analysis?ai=true`는 API로만 남아 있다.

### 여러 나라 기사 수집

- 미장 종목은 Google 뉴스 미국판에 더해 영국·인도·일본·독일·프랑스판도 조회한다(`app/sector_news.py`의 `EDITIONS`, `WORLD_EDITIONS`). 종목 기사는 전부, 미장 분야 기사는 시총 상위 2종목, 시장 분석 탭은 분야별 1종목에 적용한다. 영어권 다른 나라 판은 미국판과 겹치는 기사가 많고(엔비디아 기준 새 기사 5~15건), 일본·독일판이 현지어 기사로 20건 이상 새로 나왔다.
- 기사마다 `country`가 붙고 화면에 나라와 `수집 국가` 집계가 표시된다. 번역은 원문 언어 자동 감지로 바꿨고, 한국어·영어가 아닌 기사는 번역된 제목으로 호재/악재를 분류한다.

### 토스증권 계좌 연결·주문·관심 종목 (11-11)

- 공식 문서 확인: 계좌·자산·주문 API는 같은 앱 키(client_credentials)에 `X-Tossinvest-Account: {accountSeq}`(GET /api/v1/accounts) 헤더를 붙인다. **모의투자 환경이 없어 주문은 실제로 체결된다.** 관심 종목 API는 없다(앱 Redis에 저장). 주문은 `POST /api/v1/orders`(symbol, side BUY/SELL, orderType LIMIT/MARKET, timeInForce DAY, quantity, price, clientOrderId 중복 방지 키), 취소 `POST /api/v1/orders/{orderId}/cancel`, 목록 `GET /api/v1/orders?status=OPEN|CLOSED`.

- `app/api/account_routes.py`: `/auth/me·signup·login·logout·toss-key(등록 시 실제로 토큰 발급·계좌 조회해 확인, ip-not-allowed 안내)·trading(켤 때 비밀번호 재확인)·delete-account`. 계좌·주문·관심 종목은 로그인 필요, 관심 종목·현황 캐시·주문 확인 토큰은 사용자별(다른 사용자 토큰 거절). 요청 검사: Host가 `ALLOWED_HOSTS` 안, Origin이 같은 호스트, Sec-Fetch-Site가 cross/same-site 아님, 쓰기 요청은 `X-Toss-Order: 1`.
- 실제 주문 조건: 서버 `TRADING_ENABLED=true` + 사용자 "실제 주문 허용" + 본인 미리보기 토큰 + 금액 상한.
- 실측(임시 APP_SECRET_KEY로 띄운 서버, 테스트 계정은 끝에 삭제): 비로그인 401, 쿠키 플래그 정상, 틀린 키 400, 실제 키 연결·계좌·현황 정상, 주문 허용 켜기는 비밀번호 확인, 서버 주문 꺼짐이면 확인 거절, 쿠키 없는 다른 클라이언트 401, 탈퇴 후 남은 데이터 0. 테스트 64건 통과. requirements.txt의 붙어 있던 줄(pydantic-settings·beautifulsoup4)을 고치고 cryptography 추가.
- 공개 배포 시 할 일(아직 안 함): `.env`에 `APP_SECRET_KEY`(32자 이상, 바꾸지 말 것)·`SIGNUP_INVITE_CODE`·`ALLOWED_HOSTS`(도메인)·`SESSION_COOKIE_SECURE=true`, HTTPS 리버스 프록시(Caddy·nginx 등) 뒤에서 `uvicorn --host 0.0.0.0 --proxy-headers`, 서버 공인 IP를 각 사용자에게 알려 허용 IP에 넣게 하기. 남의 증권 계좌 키를 맡아 주문을 대신 보내는 공개 서비스는 법적 검토가 필요할 수 있다.

### 주문 가격 단위(원·달러) (11-11)

- 토스 주문 가격은 종목 거래 통화로만 보낸다(국내 원, 미국 달러. 주문 요청에 통화 필드 없음). 그래서 미국 주식은 원으로 입력하면 토스 환율 API(`GET /api/v1/exchange-rate?baseCurrency=USD&quoteCurrency=KRW`, 1분 갱신 참고값)의 매매기준율로 달러로 바꿔(1달러 이상 소수 둘째, 미만 넷째 자리) 주문하고, 국내 주식은 원만 허용(호가 단위 때문).
- 화면: 가격 옆 단위 선택(달러/원), 종목코드를 넣으면 "달러로 거래하는 미국 주식 · 최근 종가 $2.10(약 2,829원) · 1달러 = 1,347원" 같은 안내(`GET /api/v1/account/quote`). 미리보기에 "5,400원 → $4.01", 원화 환산 예상 금액, 적용 환율 표시.
- 확인: MDCX 5,400원 매도 미리보기 → $4.01, 국내 주식을 달러로 넣으면 거절. 테스트 65건 통과.

### 종목 이름으로 주문 (11-11)

- 토스 Open API에는 이름 검색이 없어, 시장별 전체 종목 목록(`GET /api/v1/stocks/all?market=KOSPI|KOSDAQ|NYSE|NASDAQ|AMEX`, 초당 1회 한도)을 서버 시작 시와 하루 한 번 받아 Redis·메모리에 두고 찾는다(`app/stock_master.py`, `GET /api/v1/stocks/search?q=`). 순서: 코드 일치 > 이름 일치 > 코드 앞부분 > 이름 앞부분 > 이름 포함, 같으면 보통주·주식 먼저, 짧은 이름 먼저. 검색 0.01초.
- 화면: 주문 칸·관심 종목 칸에 이름을 치면 아래에 후보 버튼이 뜨고, 누르면 주문 칸에 들어가거나(관심 칸은 바로 추가) 거래 통화가 표시된다. 이름만 넣고 미리보기를 누르면 추측하지 않고 "목록에서 골라 주세요". 보유 종목 표·종목 현황 카드에 매수·매도 버튼, AI분석 탭의 AI 추천 종목에 "이 종목 주문하기"(내 계좌 탭 주문 칸으로 이동).
- 한계: 인기·시가총액 정보가 목록에 없어 "삼성"처럼 넓은 검색어는 삼성화재가 삼성전자보다 먼저 나올 수 있다. 테스트 66건 통과.

### Redis 저장 방식 변경 (11-15)

- 문제: Redis가 이름 없는 임시 볼륨(`7c8fbe84…`)에 1시간 주기 스냅샷만 남겨, `docker compose down` 후 `up`이면 회원·토스 키·가상 포트폴리오가 전부 사라지고, 갑자기 꺼지면 최대 1시간분을 잃을 수 있었다.
- `docker-compose.yml`: 이름 있는 볼륨 `toss-ranking-redis-data`(down/up에도 유지, `down -v`로만 삭제), `--appendonly yes --appendfsync everysec`(1초마다 디스크 반영) + 스냅샷(900/1, 300/10, 60/10000).
- 옮긴 방법: 서버 끄기 → 키 개수 기록 → `SAVE` 후 dump.rdb 백업(세션 임시 폴더, 민감 정보라 git에 두지 않음) → 옛 컨테이너만 삭제(옛 볼륨은 남김) → 새 컨테이너 생성 후 백업 넣기. 주의: Redis 7은 appendonly를 켠 채 처음 켜면 dump.rdb를 무시하고 빈 상태로 시작한다(실제로 0건으로 시작). 그래서 같은 볼륨에 appendonly를 끈 임시 Redis로 백업을 읽고 `CONFIG SET appendonly yes`로 AOF를 만든 뒤 정상 종료, 본 컨테이너를 다시 켰다.
- 확인: 키 개수 db0 2,309·db5 147·db6 163, 회원 1·가상 포트폴리오 1·세션 1·관심 종목 1·추천 기록 1로 옮기기 전과 같음. `docker compose down`→`up` 뒤에도 그대로, 새로 쓴 값이 재시작 뒤에도 남음. 옛 임시 볼륨 `7c8fbe84…`는 되돌리기용으로 남겨 둠(확인 후 지워도 됨). 테스트 76건 통과.

### 실서버 배포 · HTTPS · 자동 운용 · 판단 모듈 · 종목 판단 기록 (11-24 ~ 11-25)

- **배포(오라클 클라우드 무료, 도쿄):** A1.Flex(ARM)는 자리 부족이라 `VM.Standard.E2.1.Micro`(x86, 1GB) + 스왑 2GB, Ubuntu 24.04, Docker. VCN을 먼저 만들어야 공용 IP를 켤 수 있었다. iptables 80·443 열기, 토스 허용 IP에 일본 서버 IP 등록(정상 응답). 서버 `.env`는 사용자가 직접 입력(TRADING_ENABLED=false, 서버에서 만든 APP_SECRET_KEY, 초대 코드). SSH는 키로만(비밀번호 꺼짐), 하루 약 100번의 봇 로그인 시도 확인 → 22번을 내 IP로만 받기는 나중에.
- **HTTPS:** `Caddyfile` + compose에 caddy(80·443, Let's Encrypt 자동), 앱은 `127.0.0.1:9000`만, uvicorn `--proxy-headers`로 실제 접속자 IP. 주소 `<IP를 -로>.sslip.io`, `SESSION_COOKIE_SECURE=true`.
- **로컬 데이터 이전:** 계정·가상 포트폴리오·추천 기록·관심 종목·번역 캐시. 개인 토스 키는 빼고(로컬 비밀값으로 암호화돼 서버에서 못 풂). Windows가 6353~6452 포트를 예약해 로컬 Redis 6379가 안 열려 `docker run --network container:...`로 읽음.
- **가상 포트폴리오:** 종료일 바꾸기(처음 종료일 보존, 세 가지 비교 묶음은 함께). 종목 수 5개 고정 제거 — AI가 추천 개수를 정함(최소 1, 후보 안), 통합 추천은 AI 추천을 모두 담음.
- **자동 운용(`app/managed.py` Book):** 매도 신호로 팔고 판 돈으로 최신 추천을 다시 삼, 새 추천 교체(rotate), 추천 수 따르기. 켜기 전 기간은 일봉으로 다시 계산해 장부의 출발점.
- **장중 매매(`app/managed_live.py`):** 장중 5분마다 현재가(일봉 오늘 봉)로 판단·매매, Redis 장부 `vp:ledger:v1:{user}:{id}`, run_id로 끄고 켤 때 새로 시작. 휴장일은 오늘 봉이 없어 거래 안 함. 미국 서머타임은 zoneinfo(tzdata 추가).
- **판단 모듈(`app/decision.py`):** 사기 — 위험 지정·단기 과열·근거 50점 미만(약세장 60)·하락 흐름 테마·당일 AI 매도 의견 제외, 근거·AI 추천·20일선·RSI로 순위, 약세장(지수 60일선 아래)이면 절반만 사고 나머지는 회복 때 투자. 팔기 — 고점 대비 −10%(약세장 −7%)·위험 지정·AI 점검 매도(장중), 추천 근거 약화·테마 흐름 하락·이익 실현(마감 무렵만). AI 점검은 시장마다 하루 1번.
- **장중 추천 갱신:** 30분마다(장 시작 20분 뒤부터). 같은 날 갱신은 후보에서 완전히 빠진 종목만 팔고, 판 종목은 그날 다시 사지 않음. 빈 추천 기록·AI 실패로 규칙 추천만 나온 기록은 쓰지 않음/덮어쓰지 않음.
- **예약 주문:** 장 마감 뒤 다음 장 시가 예약(종가·최신 추천·AI 점검), 다음 장 첫 확인 때 시가 체결, 매수는 갭 상승(+3% 초과)이면 건너뛰고 그날은 쫓아 사지 않음.
- **종목 판단 기록(`app/stock_memory.py`):** AI 추천·위험(이유 포함)·AI 점검·자동 운용 매매를 종목별로(최근 120건, 같은 종류·같은 날은 한 건), 장이 닫혀 있을 때 하루 1번 1·5·20거래일 수익률·지수 대비 채점. 판단일은 그 가격이 속한 장 날짜(`price_day`). 판단 반영(`USE_IN_DECISIONS`)은 2~4주 뒤. API `/api/v1/stock-memory`.
- 기타: 토스 종목 정보 조회 429 재시도, 포트폴리오 표의 긴 이유 문장 줄바꿈. 테스트 95→110건. 서버: CPU 약 2%, 메모리 약 90MB, Redis 약 4MB.
